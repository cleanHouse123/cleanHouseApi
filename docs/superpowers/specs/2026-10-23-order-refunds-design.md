# Возврат денег при отмене заказа — дизайн

Дата: 23.10.2026
Репозитории: `backend-mussor` (cleanHouseApi), `mussor-admin` (cleanHouseAdminPanel)

## Проблема

Отмена заказа только меняет статус: ни `cancelOrder`, ни смена статуса из админки
не инициируют возврат. Вызова `POST /refunds` в бэкенде нет вообще. Обработчик
`refund.succeeded` реагирует только на возврат, оформленный вручную в личном
кабинете YooKassa.

При этом оферта обещает возврат в течение 10 календарных дней тем же способом
оплаты (п. 8.3) и перечисляет случаи, когда он обязателен (п. 1.2, 3.5, 5.8, 5.9,
6.7). Сейчас это ручная операция, о которой система не напоминает: отменённый
оплаченный заказ в админке выглядит как отменённый неоплаченный.

## Почему не автоматический возврат на каждую отмену

Отмена не равна возврату:

- п. 5.7 — вынос не выполнен по вине заказчика: стоимость **не возвращается**;
- п. 8.2 — при поздней отмене удерживаются фактически понесённые расходы;
- п. 6.7 — по подписке возвращается остаток по формуле, а не вся сумма.

Возврат на карту необратим, поэтому решение принимает человек. Автоматический
полный возврат уместен только там, где вина не клиента (адрес вне зоны, слот
недоступен, не оказано по вине исполнителя) — это отдельный следующий шаг.

## Решение

Отмена и решение по деньгам — одно действие. Админ не может отменить оплаченный
заказ, не выбрав, что делать с оплатой.

### Данные

К `Payment` добавляются поля решения:

| Поле | Назначение |
|---|---|
| `refundStatus` | `none` (решено не возвращать), `pending`, `succeeded`, `canceled` |
| `refundAmount` | сумма возврата в рублях (как и `amount`) |
| `refundId` | идентификатор возврата в YooKassa |
| `refundReason` | причина: обязательна при отказе в возврате |
| `refundDecidedAt` / `refundDecidedBy` | когда и кто решил |

### Сервис возврата

`RefundService` обращается к API YooKassa напрямую: метод библиотеки
`createRefund` возвращает только полную сумму платежа и генерирует случайный
ключ идемпотентности на каждый вызов, что при повторе даёт второй возврат.

- ключ идемпотентности детерминированный: `refund-{paymentId}-{amountInKopecks}`,
  поэтому повтор запроса не создаёт второй возврат;
- учётные данные берутся так же, как при создании платежа, включая
  `YOOKASSA_USE_TEST_MODE`;
- при `YOOKASSA_MOCK_PAYMENTS=true` возврат имитируется.

### Эндпоинты

`POST /orders/:id/cancel-with-refund` (админ) — тело:
`{ refund: 'full' | 'partial' | 'none', amount?: number, reason?: string }`.
Отменяет заказ и в той же операции оформляет решение по деньгам. Частичный
возврат требует сумму, отказ требует причину.

`GET /orders/refunds/pending` (админ) — оплаченные отменённые заказы без решения
по возврату, с датой отмены: страховка на случай, когда возврат упал с ошибкой
или заказ отменили в обход диалога.

### Админка

У оплаченного заказа кнопка «Отменить» открывает диалог с выбором: вернуть
полностью, вернуть часть (сумма), без возврата (причина). Отдельная вкладка
«Ожидают возврата» со списком из второго эндпоинта.

## Вне объёма

- Возврат по подписке с расчётом по формуле п. 6.7 — следующим шагом.
- Автоматический возврат при отмене по вине исполнителя.

## Проверка

Юнит-тесты на сервис возврата (идемпотентность, частичная сумма, отказ) и на
ветки эндпоинта. На тестовом магазине YooKassa — полный и частичный возврат с
проверкой статуса по вебхуку.
