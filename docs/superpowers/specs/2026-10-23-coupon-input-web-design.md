# Ввод промокода в веб-клиенте — дизайн

Дата: 23.10.2026
Репозитории: `backend-mussor` (cleanHouseApi), `clenHouseWeb`

## Задача

Промокоды заводятся в админке и принимаются API, но клиенту ввести их негде: ни в
оформлении заказа, ни при покупке подписки поля нет. Нужно добавить поле ввода в
веб-клиенте для обоих сценариев.

## Исходное состояние

- `POST /orders` принимает `couponCode`. Купон применяется при создании заказа:
  невалидный код — заказ не создаётся.
- `POST /subscriptions/payment/create` принимает `couponCode`.
- `POST /coupons/validate` считает превью только для `scope=subscription` и требует
  `planId`; для заказов отвечает «Превью для заказов пока не поддерживается».
- Купон на заказ **вытесняет** автоскидку «первый заказ за 1 ₽»
  (`skipFirstOrderDiscount: applyCoupon` в `order.service.ts`): действует одна скидка,
  купон в приоритете. Поэтому промокод может оказаться невыгодным.

## Решения

1. Превью для заказов добавляем на бэкенд — клиент ведёт себя одинаково в обоих
   сценариях: ввёл код, сразу увидел скидку и итог.
2. Если промокод невыгоднее скидки на первый заказ — предупреждаем и оставляем выбор
   клиенту, логику приоритета на бэкенде не трогаем.

## Бэкенд

**`ValidateCouponDto`** — поля для расчёта цены заказа: `numberPackages`, `addressId`,
`address`, `addressDetails`. Все опциональные, используются только при `scope=order`.

**`CouponValidationResponseDto`** — добавляется `priceWithoutCoupon`: цена, которую
клиент заплатил бы без кода (с автоскидкой первого заказа). Фронт сравнивает её с
`finalAmount` и показывает предупреждение.

**`CouponService.validateForPreview`** — ветка `scope=order`: базовая цена считается
через `priceService.getOrderPrice({ ..., skipFirstOrderDiscount: true })`, тем же
вызовом, что и при создании заказа, чтобы превью не расходилось с фактом. Отдельным
вызовом с `skipFirstOrderDiscount: false` считается `priceWithoutCoupon`.

**`CouponModule`** импортирует `PriceModule` (обратной зависимости нет, цикла не будет).

**Тест** на ветку превью для заказа.

## Фронт

**`src/modules/coupons/`** — api, типы, хук `useCouponPreview`, компонент `CouponField`,
по образцу модулей `price` и `referral`.

**`CouponField`** — свёрнутая ссылка «У меня есть промокод» раскрывает инпут и кнопку
«Применить». После успеха: «Промокод X применён, −Y ₽» и «Убрать». Ошибка бэкенда
показывается под полем. Если `priceWithoutCoupon < finalAmount` — предупреждение
«Без промокода этот заказ стоит N ₽».

**Заказ** — поле в `CreateOrderModalWithTabs` над блоком с ценой и кнопкой; код уходит
в `OrderFormData.couponCode` и дальше в `POST /orders`.

**Подписка** — поле на странице подписок перед оплатой; код прокидывается в
`createSubscriptionPayment`. Три точки вызова: новая подписка, оплата существующей,
хук `useSubscriptions`.

## Проверка

`nest build` и jest на бэкенде, `yarn build` на фронте. На проде: завести промокод в
админке, применить в вебе, сверить итог с превью. Платёж не доводится.
