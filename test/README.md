# Прогон бизнес-флоу

Поднимает настоящее приложение на отдельной базе и проходит сценарии через
HTTP — так же, как ходят веб-клиент и админка. Платежи и возвраты идут в
mock-режиме, в YooKassa не уходит ни одного запроса.

## Запуск

```bash
docker run -d --name mussor-e2e \
  -e POSTGRES_PASSWORD=test -e POSTGRES_DB=mussor_e2e \
  -p 55499:5432 postgres:16-alpine

DATABASE_HOST=127.0.0.1 DATABASE_PORT=55499 DATABASE_USER=postgres \
DATABASE_PASSWORD=test DATABASE_NAME=mussor_e2e npm run test:e2e
```

База нужна пустая и **не та, где живут настоящие данные**: схема создаётся
через `synchronize`, тесты пишут в неё напрямую.

## Что покрыто

- **Заказы и возвраты** — оплата через платёж и webhook, полный и частичный
  возврат, отказ с причиной, одно решение на заказ, очередь ожидающих
  возврата, чужой заказ.
- **Подписки** — покупка и активация, заказ из лимита, правило трёх часов в
  обе стороны и флаг администратора, возврат выноса в ту подписку, из которой
  он был списан, заморозка по пункту 6.4 и понятные отказы на паузе, отказ от
  подписки с расчётом по пункту 6.7 Оферты, повторное решение, чужая подписка.
- **Расписания** — создание только подписчиком, дни недели числами, движок
  создаёт заказ на подошедший вынос и не создаёт второй, смена частоты
  включает расписание сразу, доступ к чужому расписанию.
- **Курьеры** — созданный администратором курьер входит в приложение, пароль
  не возвращается и хранится хешем, слабый и пустой пароль не принимаются,
  смена пароля администратором, чужим создание закрыто.
- **Заказы рядом** — эндпоинт отвечает, считает расстояние в метрах,
  сортирует от ближнего к дальнему, не даёт NaN в совпадающей точке.
- **Работа курьера** — взять, начать, завершить; чужим именем не взять,
  чужой заказ не начать и не отменить, взятый не перехватить, неоплаченный
  не взять; переназначение только администратором.

## Чего тесты не видят

Интерфейсы: вёрстку, тексты на экранах, поведение форм. Для них отдельный
ручной чек-лист.
